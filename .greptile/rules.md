# Greptile repository review rules

Follow `AGENTS.md` where present and review changed code against the actual upstream project requirements.

- No secrets, personal data or proprietary materials in public builds, screenshots, review logs or media prompts.
- No emails, messages, applications, course submissions, invitations or other outward communications without explicit separate approval.
- No paid AI inference, new subscription or remote code-execution flow without opt-in. Dry-run first.
- Separate *configured*, *installed*, *authenticated*, *tested* and *production-verified* statuses.
- Prefer maintained, license-compatible upstream open source; test integration compatibility and preserve working behavior.
- Report concrete file/line evidence, observed failure and a minimal fix. Do not invent passing CI or completed deadlines.

## Project-specific checks

Require real-vs-synthetic provenance, reproducible scientific evidence and exact test commands. Reject private orchard boundaries, private sensors, proprietary aerial imagery or invented satellite results.

Greptile is activated only after the owner connects/authorizes the Greptile app; committing rules alone does not authorize code access.
