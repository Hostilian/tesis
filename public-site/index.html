Geospatial research software demonstrator

A prototype for exploring an evidence-led Earth-observation workflow: source discovery, provenance, quality checks, processing, evaluation and visualization.

Prototype Scope pending formal confirmation

Data and results notice

The example records and earlier dashboard views include mock or synthetic inputs. They are not verified observations or ground truth. Historical performance and economic statistics are withheld as thesis findings until their source data, run records, calculations and validation can be independently reviewed.

Scope

The formal assignment controls the research question. Retaining the existing approved topic is the working default; a bounded agricultural case is only a proposal until the supervisor and any required academic process approve it. A full multi-sensor study is deferred.

Version 2

A separate provisional working draft is being prepared privately. It keeps the original thesis source intact, explains proposed changes, distinguishes evidence from plans, and leaves empirical results, discussion and conclusions for the student author.

Privacy

This site omits student identifiers and personal contact details. It does not contain private boundaries, partner records, credentials or imagery. It uses no third-party analytics or external scripts.

What this revision changes

  • Replaces the claim-led dashboard landing page with a status and evidence-policy page.
  • Removes personal contact details and unverified headline statistics from the Pages artifact.
  • Stops publishing alternate dashboard editions and raw data directories through Pages.
  • Explains that mock outputs are software demonstrations, not evidence of real events.
  • Provides a separate summary of the Version 2 changes and the evidence policy.

Evidence gates before scientific claims

  1. Confirm the registered question and study scope from the formal academic record.
  2. Record the exact public data product, item, dates, bands, license and processing configuration.
  3. Preserve the run command, versions, commit, logs and output checksums.
  4. Use an appropriate independent reference for any accuracy or hypothesis claim.
  5. Have the student author interpret results and state limitations.
